## 前言

学 Qt 到一定程度，总得做个像样的东西练手。计算器逻辑不复杂，界面也不难拖，看起来是标准的"新手项目"。但真要做到顺手——错误提示友好、异常状态下按钮行为正确、样式有按压反馈——要处理的东西比想象中多。

我的版本功能包括：基础四则运算、连续运算、小数输入、正负号切换、百分比 / 平方 / 开方 / 倒数四个一元运算、退格、C / CE 两级清除，以及完整的错误态处理。下面按开发顺序展开。

## 一、先定架构：状态与显示分离

动手前先定了一条规矩：**计算状态全部存在成员变量里，界面控件只做渲染输出**。

具体就是这几个成员变量：

```cpp
QString m_current;      // 当前正在输入的数字串
double  m_accumulator;  // 左操作数
QString m_pendingOp;    // 待执行的运算符
bool    m_isNewEntry;   // 下次按数字是否重新开始输入
```

所有状态变化都走统一的 `updateDisplay()` 刷新显示，**绝不从标签文本里反读状态**。

这条规矩看起来多余，实际上救了我好几次。比如后面做错误态时，如果状态靠"标签上显示的是不是'错误'"来判断，那文案一改逻辑就全线失效。状态是状态，显示是显示，两套东西分开存——这是整个项目里最值钱的设计决定。

按钮事件用的是 Qt 的自动连接机制：槽函数按 `on_<对象名>_clicked` 命名，`connectSlotsByName` 自动挂上，24 个按钮每个对应一个槽，直观省事。

## 二、输入状态机：一个 isNewEntry 顶半边

计算器交互的核心，其实是搞清楚"用户现在是不是在输入一个新数"。

- 按 `5`、`+` 之后按 `3`：`3` 应该**替换**当前显示，而不是拼成 `53`；
- 正在输入 `12` 时按 `3`：应该拼成 `123`；
- 当前是单个 `0` 时按 `5`：应该替换成 `5`，不能出现 `05` 这种前导零。

这三条全靠 `m_isNewEntry` 一个布尔量调度：按运算符、按等号、执行一元运算之后都置 `true`，按数字后置 `false`。

其中**一元运算之后必须置 `true`** 是我印象最深的一处：`5`、`x²` 之后显示 `25`，这时再按 `2`，如果忘了置位，结果就是 `252`——数字拼到了运算结果的尾巴上。这类 bug 不点不知道，一点吓一跳。

## 三、除零异常：一个错误，两种文案

除零是计算器绕不开的异常，但我没有把它做成单一提示，而是分了两种情况：

- `0 ÷ 0`：数学上**结果未定义**；
- 非 0 除以 0：**除数不能为零**。

实现本身不难，难的是错误态的管理方式。最初的写法是在除法分支里直接把标签设成错误文案，然后用"当前显示是否等于错误文案"来判断是否处于错误态——很快就被打脸：文案改一个字，所有判断全失效，而且正常输入理论上也可能撞上这些字。

修正后的方案是把**错误状态和错误文案分开存**：

```cpp
bool    m_isError;   // 错误态标记
QString m_errorMsg;  // 错误提示文案
```

`updateDisplay()` 里根据 `m_isError` 决定显示 `m_errorMsg` 还是 `m_current`。状态判断走 bool，文案随便改，互不影响。

顺带把其余异常也统一了：开方遇到负数、倒数遇到零，都走同一个 `showError()` 入口。进入错误态时顺便清掉 `m_accumulator` 和 `m_pendingOp`，避免带着脏状态恢复。

## 四、错误态交互：禁用容易恢复难

错误态的交互需求是：**只允许输入数字，运算符及其他功能按钮自动禁用变暗；退出错误态时恢复可用**。

听起来简单，实现时连踩三个坑。

### 坑一：Qt 会自动变灰，但自定义样式不会

普通按钮 `setEnabled(false)` 之后 Qt 默认就有变灰效果，但按钮一旦上了自定义 QSS 样式，禁用态就不再自动处理了——必须手动补 `:disabled` 伪类规则，否则按钮禁用了却看不出任何变化。

### 坑二：首次按数字不生效

错误态下按数字应该清错误、开始新输入并恢复按钮，但实际效果是第一次按数字界面没反应，要按第二次才行——当时的现象是屏幕上出现"66"。排查后发现：错误是在运算过程中进入的，进入路径上漏了恢复逻辑，导致第一次按键只做了"退出错误态"，没有把新数字显示出来。

### 坑三：提前 return 吞掉了恢复逻辑

修复过程中又发现，有些分支里恢复按钮的代码写在 `return` 之后，永远不会执行。教训具体而深刻：**提前 return 的分支，分支内所有逻辑必须放在 return 语句之前**。

---

修着修着还发现一个设计问题：C、CE、等号、退格这四个按键在错误态下都需要"复位并恢复按钮"，如果各自写一遍恢复逻辑，改一处漏一处。于是抽了一个公共的 `resetAll()`：

```cpp
void MainWindow::resetAll()
{
    m_current = "0";
    m_accumulator = 0;
    m_pendingOp.clear();
    m_isNewEntry = true;
    m_isError = false;
    m_errorMsg.clear();
    setOpsEnabled(true);   // 恢复按钮
    updateDisplay();
}
```

错误态下按数字、C、CE、等号、退格，殊途同归都走复位，重复代码清零。这条经验后来证明非常有用：**同类复位需求出现三次以上，就该收敛成一个函数**。

## 五、显示格式与退格的细节

结果显示用的是：

```cpp
QString::number(value, 'g', 15);
```

`'g'` 格式加 15 位有效数字是个很舒服的组合：既能保留 double 的精度，又会自动去掉浮点运算的噪声（`0.1 + 0.2` 不会显示成 `0.30000000000000004`）和末尾多余的零。

退格用的 `QString::chop(n)` 也记一笔：它是**直接修改原字符串、没有返回值**的方法，从末尾删 n 个字符，不需要也不能写 `s = s.chop(1)`。删完还要检查：删空了、或者只剩一个负号，就回 `"0"`——保证 `m_current` 任何时刻都是合法数字串，后面的 `toDouble()` 才不会翻车。

## 六、样式：QSS 三态的几条规矩

视觉上要求所有按钮浅色系、字体统一黑色、数字键和运算符键有区分度。最终定的方案是：数字键白色系、运算符和功能键浅蓝色系（反复调了几次饱和度才到"看得出区别又不刺眼"的程度）、等号蓝底白字。

样式实现上踩的坑，拼成几条规矩：

### 规矩一：样式统一写在按钮父容器的 styleSheet 里

在 Qt Designer 里配置一次，所有按钮按类型分规则匹配，避免 24 个按钮逐个设置——改一个圆角要改 24 处的滋味不好受。

### 规矩二：`:pressed` 必须写在 `:hover` 之后

QSS 按声明顺序匹配，反过来的话按下状态会被 hover 规则覆盖，按钮永远没有按压反馈。

### 规矩三：带 ID 选择器的按钮必须单独补全三态

类似 `#Btn_equals { ... }` 这种更具体的选择器会覆盖通用规则，等号键想有 hover / pressed / disabled 效果，三条伪类都得在它自己的规则里写全，一条都不能省。

## 七、零散但值得记的坑

- **窗口图标不在 Qt Designer 里设。** `windowIcon` 属性通常不暴露在属性编辑器中，图标要在 `main.cpp` 里用 `QApplication::setWindowIcon()` 设置。
- **资源路径用 `:/` 前缀。** 直接写相对路径，Qt Creator 的运行时工作目录和工程目录对不上时就找不到文件；qrc 资源前缀从根上杜绝这个问题。

## 八、总结

一个计算器写下来，真正花时间的不是四则运算那几行算术，而是状态管理和异常交互：

1. **状态与显示分离**是地基，后面错误态能顺利重构全靠这个底子；
2. **错误状态与错误文案分开存**，字符串当状态用迟早出事；
3. **错误态的难点在恢复**：进入错误态只要一处代码，恢复却散布在每个可能的出口，收敛成 `resetAll()` 一处定义；
4. **自定义样式要自己负责禁用态**，`:disabled` 伪类和三态优先级都得手动照顾；
5. 提前 return 的分支，逻辑要全放在 return 之前——这条是用 bug 换来的。
